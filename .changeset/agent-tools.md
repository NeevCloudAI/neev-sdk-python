New `neevai.agent_tools` module: the sandbox tool contract for building your own agent, with no framework dependency. `SandboxTools(sandbox, *, allow_preview=False, allow_rollback=False, allow_processes=False)` exposes `run_command`, `write_file`, `read_file`, `expose_port`, `checkpoint`, `rollback`, `start_process`, `read_process_output` and `stop_process`, each returning a JSON-serializable dict typed as a `TypedDict` (`RunCommandToolResult`, `ReadProcessOutputToolResult`, ... or `ToolErrorResult`). `names()` lists the enabled tools, `DESCRIPTIONS` and `PARAMETERS` hold each tool's model-facing description and JSON Schema, and `call(name, args)` runs a tool call by name. `AsyncSandboxTools` wraps an `AsyncSandbox` with the same methods as coroutines. `allow_preview` or `allow_rollback` on a handle without client context raises `ValueError`.

The model sees the same text as from the JS SDK. Errors it can fix return `{"error": ...}` while auth, rate-limit, server and network errors raise. An API error reads `HTTP <status> <code>: <message>`, leaving out the code or message when absent and never including the request method, URL or request id; the message is the first non-empty string among the body's `message`, `error` and `details`, and a body that is not a JSON object is used as raw text. A file that is not UTF-8 returns `not UTF-8 text`, while command output keeps its text with U+FFFD in place of bad bytes. A command silent long enough for the network edge to answer 524 returns an error result pointing at `start_process`. Every error text keeps its first line, at most 500 characters, and output is capped at 10 KB per stream.

`call()` never raises for model input: an unknown or disabled tool, arguments that are not an object, an unknown key (checked first), a missing required key, or a property of the wrong type each return an error result, with key names quoted as JSON (`missing a required argument: "path"`). `timeout_s` and `wait_s` accept numbers or plain ASCII decimal strings: through `call()` anything else is an error result, while a direct method call falls back to the default; `timeout_s` rounds to milliseconds half up. `read_process_output` takes `wait_s` (0 to 60) to wait for a running process to exit before reading.

`DESCRIPTIONS` and `PARAMETERS` are read-only at every level and JSON-serializable, with real lists inside the schemas; `copy.copy`, `copy.deepcopy` and `pickle` give plain dicts and lists for frameworks that rewrite a copied schema.

Error parsing is shared by the runtime and lifecycle transports. A runtime error's `APIError.body` is now the parsed response body (before it held only `code` and `message`), with `code` taken from sandboxd's `reason_code` when `code` is absent or empty, so `details` and `str(error)` now include sandboxd's `error` and `details` fields. Lifecycle errors fall back to `reason_code` for `code` the same way. An error body that is not a JSON object, such as `[1,2]` or `null`, is kept as raw `details` text instead of crashing the runtime transport with `AttributeError`, and one leading byte order mark is dropped from any error body.
