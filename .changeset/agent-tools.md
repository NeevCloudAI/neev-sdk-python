New `neevai.agent_tools` module: the sandbox tool contract for building your own agent, with no framework dependency. `SandboxTools(sandbox, *, allow_preview=False, allow_rollback=False, allow_processes=False)` exposes `run_command`, `write_file`, `read_file`, `expose_port`, `checkpoint`, `rollback`, `start_process`, `read_process_output` and `stop_process`, each returning a JSON-serializable dict typed as a `TypedDict` (`RunCommandToolResult`, `ReadProcessOutputToolResult`, ... or `ToolErrorResult`). `names()` lists the enabled tools, `DESCRIPTIONS` and `PARAMETERS` hold each tool's model-facing description and JSON Schema (both read-only and JSON-serializable), and `call(name, args)` runs a tool call by name, returning an error result for an unknown or disabled tool or arguments that do not fit. Command output with bytes that are not UTF-8 keeps its text with U+FFFD in their place, and a command silent long enough for the network edge to answer 524 returns an error result pointing at `start_process`. Output is capped at 10 KB per stream, and errors the model can fix return `{"error": ...}` while auth, rate-limit, server and network errors raise. `call()` checks argument types against `PARAMETERS` and never raises for model input. `timeout_s` and `wait_s` accept numbers or plain decimal strings; anything else takes the default. `read_process_output` takes `wait_s` (0 to 60) to wait for a running process to exit before reading. `allow_preview` or `allow_rollback` on a handle without client context raises `ValueError`. `AsyncSandboxTools` wraps an `AsyncSandbox` with the same methods as coroutines.
